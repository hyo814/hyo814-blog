# [ZBF] 7주차 보충 : 도메인 주도 설계(Domain-Driven Design, DDD)

> 이 글은 [네이버 블로그](https://blog.naver.com/ggamjige8888/223496493728)에 2024년 6월 30일에 올렸던 것을 그대로 옮겨온 것입니다.

도메인 주도 설계(Domain-Driven Design, DDD)는 복잡한 소프트웨어 시스템을 설계하고 개발하는 데 필요한 철학과 방법론을 제공합니다. 이는 비즈니스 도메인(업무 영역)을 중심으로 소프트웨어를 설계하여, 변화하는 비즈니스 요구사항에 유연하게 대응할 수 있는 시스템을 만드는 것을 목표로 합니다.

**도메인 주도 설계의 개념**

**1. 도메인**

도메인은 소프트웨어가 해결하고자 하는 문제 영역을 의미합니다. 예를 들어, 전자상거래 시스템의 도메인은 제품 관리, 주문 처리, 결제 등입니다.

**2. 유비쿼터스 언어**

유비쿼터스 언어(Ubiquitous Language)는 개발팀과 비즈니스 팀 간의 의사소통을 원활하게 하기 위해 사용하는 공통의 언어입니다. 이를 통해 오해를 줄이고, 명확한 요구사항을 도출할 수 있습니다.

**3. 전략적 설계**

전략적 설계는 시스템의 전체 구조를 설계하는 과정으로, 도메인 모델을 통해 비즈니스 로직을 표현하고, 이를 통해 시스템을 설계합니다. 주요 개념으로는 바운디드 컨텍스트(Bounded Context)와 컨텍스트 매핑(Context Mapping)이 있습니다.

- **바운디드 컨텍스트**: 도메인을 논리적으로 구분한 경계를 의미합니다. 각 바운디드 컨텍스트는 독립적인 모델을 가지며, 명확한 경계를 통해 책임을 분리합니다.
- **컨텍스트 매핑**: 여러 바운디드 컨텍스트 간의 관계를 정의하고, 상호작용을 명확히 합니다.

**4. 전술적 설계**

전술적 설계는 개별 바운디드 컨텍스트 내의 세부 설계를 의미합니다. 주요 패턴으로는 엔티티(Entity), 밸류 오브젝트(Value Object), 애그리게잇(Aggregate), 리포지토리(Repository), 서비스(Service) 등이 있습니다.

- **엔티티**: 고유한 식별자를 가지며, 상태가 변할 수 있는 객체입니다.
- **밸류 오브젝트**: 식별자가 없으며, 불변 객체로 주로 속성을 나타냅니다.
- **애그리게잇**: 관련 객체들을 하나의 군집으로 묶은 개념으로, 일관성을 유지하기 위한 경계를 정의합니다.
- **리포지토리**: 엔티티의 영속성을 관리하는 객체입니다.
- **서비스**: 도메인 로직을 캡슐화하여 제공하는 객체입니다.

```js
// User.ts (엔티티)
class User {
  constructor(private id: string, private name: string) {}

  changeName(newName: string) {
    this.name = newName;
  }
}

// UserRepository.ts (리포지토리)
interface UserRepository {
  save(user: User): void;
  findById(userId: string): User | null;
}

// UserService.ts (서비스)
class UserService {
  constructor(private userRepository: UserRepository) {}

  changeUserName(userId: string, newName: string) {
    const user = this.userRepository.findById(userId);
    if (user) {
      user.changeName(newName);
      this.userRepository.save(user);
    }
  }
}
```

Node.js와 TypeScript를 사용하여 DDD의 전술적 설계를 구현한 것입니다. User 엔티티는 사용자 정보를 나타내고, UserRepository는 사용자 정보를 영속화하며, UserService는 사용자 이름 변경 로직을 캡슐화합니다.

---

DDD를 적용할 때 Node.js와 TypeScript를 사용하는 장점은 무엇인가요?

**1. 타입 안전성(Type Safety)**

TypeScript는 정적 타입을 제공하여 코드 작성 시 타입 검사를 수행합니다. 이는 런타임 오류를 줄이고, 코드의 안정성을 높이는 데 도움을 줍니다. DDD에서는 복잡한 도메인 로직을 다루기 때문에, 타입 안전성은 매우 중요합니다.

```js
class User {
  constructor(private id: string, private name: string) {}

  changeName(newName: string) {
    this.name = newName;
  }
}

const user = new User(1, 'Alice'); // 컴파일 오류: '1'은 'string'에 할당할 수 없습니다.
```

**2. 객체 지향 프로그래밍(OOP) 지원**

TypeScript는 클래스, 인터페이스, 상속 등 객체 지향 프로그래밍(OOP) 기능을 지원합니다. DDD는 엔티티, 밸류 오브젝트, 애그리게잇 등 OOP 개념을 기반으로 하기 때문에, TypeScript의 OOP 기능을 활용하면 DDD 패턴을 자연스럽게 적용할 수 있습니다.

```js
class User {
  constructor(private id: string, private name: string) {}

  changeName(newName: string) {
    this.name = newName;
  }
}

interface UserRepository {
  save(user: User): void;
  findById(userId: string): User | null;
}
```

**3. 풍부한 개발 도구 지원**

TypeScript는 VSCode와 같은 IDE에서 강력한 코드 자동 완성, 리팩토링, 디버깅 기능을 제공합니다. 이는 개발자의 생산성을 높이고, 코드 품질을 유지하는 데 도움이 됩니다. Node.js와 TypeScript를 함께 사용하면 이러한 도구의 이점을 극대화할 수 있습니다.

**4. 대규모 코드베이스 관리 용이**

TypeScript는 모듈화와 네임스페이스를 지원하여 대규모 코드베이스를 관리하기 쉽게 만듭니다. DDD에서는 도메인 모델을 여러 모듈로 나누어 관리하는 것이 일반적이므로, TypeScript의 모듈화 기능은 이를 효율적으로 관리하는 데 유용합니다.

```js
// models/User.ts
export class User {
  constructor(private id: string, private name: string) {}

  changeName(newName: string) {
    this.name = newName;
  }
}

// repositories/UserRepository.ts
import { User } from '../models/User';

interface UserRepository {
  save(user: User): void;
  findById(userId: string): User | null;
}
```

**5. JavaScript와의 호환성**

TypeScript는 JavaScript의 상위 집합으로, 기존 JavaScript 코드와 호환됩니다. 이는 기존 Node.js 프로젝트에 점진적으로 TypeScript를 도입할 수 있게 하여, 큰 변화 없이 타입 안전성과 OOP의 이점을 누릴 수 있게 합니다.

**6. 비동기 처리와 성능**

Node.js는 비동기 I/O를 기반으로 하여 높은 성능과 확장성을 제공합니다. DDD를 적용한 시스템에서도 이러한 성능상의 이점을 그대로 활용할 수 있습니다. TypeScript는 async/await 문법을 통해 비동기 코드를 더 직관적이고 가독성 있게 작성할 수 있게 합니다.

```js
async function getUser(userId: string, userRepository: UserRepository): Promise<User | null> {
  return await userRepository.findById(userId);
}
```

**7. 커뮤니티와 생태계**

Node.js와 TypeScript는 방대한 커뮤니티와 생태계를 가지고 있습니다. 이는 다양한 라이브러리와 도구를 쉽게 사용할 수 있게 하며, 문제 발생 시 커뮤니티의 지원을 받을 수 있는 장점이 있습니다.

---

DDD를 적용할 때 TypeScript의 타입 시스템이 어떻게 도움이 되나요?

**정확한 도메인 모델링**:

- TypeScript의 타입 시스템은 도메인 모델을 정확하게 정의할 수 있게 해줍니다. 도메인 엔티티, 밸류 오브젝트(Value Object) 등을 타입으로 명확히 정의할 수 있어, 비즈니스 로직이 타입 시스템에 의해 검증됩니다.

**타입 안전성(Type Safety)**:

- TypeScript는 컴파일 시점에 타입 오류를 검출하여 런타임 오류를 줄입니다. 이는 도메인 로직의 무결성을 보장하고, 개발자가 실수로 잘못된 데이터를 처리하지 않도록 도와줍니다.

**코드 자동 완성과 리팩토링**:

- 타입 시스템은 코드 자동 완성과 리팩토링을 쉽게 만듭니다. 이는 복잡한 도메인 로직을 다룰 때 매우 유용하며, 개발 생산성을 높입니다.

Node.js의 비동기 I/O 처리 방식이 DDD와 어떻게 잘 맞는지 설명해주세요.

**고성능 및 확장성**:

- Node.js는 비동기 I/O를 기반으로 하여 높은 성능과 확장성을 제공합니다. DDD에서 복잡한 도메인 로직을 처리하면서도 비동기 작업(예: 데이터베이스 쿼리, 외부 API 호출 등)을 효율적으로 처리할 수 있습니다.

**비동기 프로그래밍 모델**:

- Node.js의 async/await 문법은 비동기 코드를 동기 코드처럼 읽기 쉽게 만들어 줍니다. 이는 DDD의 복잡한 도메인 로직을 구현할 때 가독성과 유지보수성을 높이는 데 도움이 됩니다.

**이벤트 주도 아키텍처**:

- Node.js는 이벤트 주도 아키텍처를 지원하여, 도메인 이벤트를 쉽게 처리할 수 있습니다. 도메인 이벤트는 DDD에서 중요한 역할을 하며, 시스템 간의 느슨한 결합을 유지하면서 비즈니스 로직을 구현할 수 있습니다.
