# FontAwesome 6.7.2 → 7.2.0 업그레이드 체크리스트

FontAwesome 7.x가 나온 지 좀 됐는데 미루던 업그레이드를 정리했습니다. 메이저 버전이라 깨질 가능성이 있어 부담스러웠는데, 막상 해보니 큰 사고는 없었지만 잔잔히 체크할 게 몇 가지 있었어요. 기록 차원으로 남깁니다.

---

## 1. 왜 7.x로 올리는가

6.x 라인은 더 이상 새 아이콘이 추가되지 않고 7.x에 신규 아이콘과 스타일 변형이 몰리고 있었습니다. 디자인 팀에서 7.x에 추가된 일부 아이콘을 쓰고 싶다는 요청이 들어왔고, 이참에 라이브러리 자체를 올리기로 했어요.

부가 동기:

- CSS 트리쉐이킹이 7.x에서 더 잘 동작 (사용하지 않는 아이콘 비중 줄어듦)
- 6.x EoL은 아직 멀지만 마이그레이션 비용을 미루면 더 커질 가능성

---

## 2. 업그레이드 전 체크리스트

다음 항목을 미리 정리했습니다.

| 항목 | 확인 방법 |
|------|----------|
| 어떤 아이콘을 어디에서 쓰는지 인벤토리 | `grep -r "fa-" templates/ static/` |
| 7.x에서 이름이 바뀐 아이콘 후보 | FontAwesome 공식 [Migration Guide](https://fontawesome.com/v7/docs/web/setup/upgrade) 비교 |
| 사용 중인 스타일(`fas`, `far`, `fab`) 분포 | 위 grep 결과를 스타일 prefix 별로 분류 |
| 커스텀 CSS에서 아이콘 단위 코드(`\f...`) 직접 참조 여부 | `grep -r "content: \"\\\\f" static/css/` |

마지막 항목이 가장 위험합니다. 의사 클래스에서 `content: "\f007"` 같은 식으로 아이콘 유니코드를 직접 박아 쓴 코드는 7.x에서 코드포인트가 바뀌면 침묵 깨짐(silent break)이 됩니다.

---

## 3. 실제로 깨졌던 부분

업그레이드 후 문제가 생긴 위치들:

### 3.1 `fa-user-edit` → `fa-user-pen`

6.x에서 alias로 동작하던 일부 아이콘이 7.x에서 표시 안 됐습니다. 7.x는 더 엄격해서 deprecated alias를 더 이상 받아주지 않는 경향이었어요.

```html
<!-- 변경 전 -->
<i class="fas fa-user-edit"></i>

<!-- 변경 후 -->
<i class="fas fa-user-pen"></i>
```

### 3.2 `fa-thumbs-o-up` 류 outline 아이콘

`-o-` suffix로 outline을 표시하던 옛 명명 규칙이 완전히 빠졌습니다. `far` 스타일 prefix로 옮겨야 했어요.

```html
<!-- 변경 전 -->
<i class="fa fa-thumbs-o-up"></i>

<!-- 변경 후 -->
<i class="far fa-thumbs-up"></i>
```

### 3.3 커스텀 CSS의 유니코드 직접 참조

`pagination`, `breadcrumb` 등 일부 컴포넌트에서 `::after { content: "\f054" }` 식으로 chevron 아이콘 유니코드를 직접 쓰던 코드가 있었습니다. 7.x에서 일부 코드포인트가 재배치돼서 다른 아이콘이 표시되는 침묵 깨짐이 발생.

방어 방법은 두 가지였고, 둘 다 적용했습니다:

```css
/* 변경 전 — 깨지기 쉬움 */
.breadcrumb-item::after {
  font-family: "Font Awesome 6 Free";
  content: "\f054";
}

/* 변경 후 — 명시적 버전 & 클래스 이름 사용 */
.breadcrumb-item::after {
  font-family: "Font Awesome 7 Free";
  font-weight: 900;
  content: "\f054";  /* 그래도 코드포인트 검증 필요 */
}
```

가능하면 아예 `<i class="fas fa-chevron-right"></i>` 같은 마크업으로 빼고, CSS pseudo-element에 의존하지 않는 게 장기적으로 더 안전합니다.

---

## 4. 업그레이드 후 회귀 점검

| 페이지 | 확인 |
|--------|-----|
| 헤더/푸터 | 로고 아이콘, 소셜 아이콘 표시 OK |
| 네비게이션 메뉴 | dropdown chevron 정상 |
| 카드/리스트 | edit/delete 아이콘 정상 |
| 페이지네이션 | prev/next chevron 정상 (CSS 의존 부분이라 별도 체크) |
| 폼 | calendar/clock 아이콘 정상 |
| 모달 | close (×) 아이콘 정상 |

마지막에 빠진 곳이 항상 나오는 게 신기한데, 이번엔 *"고객지원 페이지의 카테고리 칩"*에 깨진 아이콘 하나가 있었어요. 자주 안 들어가는 페이지였습니다.

---

## 5. 이 체크리스트가 놓친 것

**① `grep -r "fa-"`로는 동적으로 만드는 아이콘이 안 잡힙니다.**

인벤토리를 grep으로 떴는데, **JS가 문자열을 조립해 클래스를 만드는 경우는 검색에 안 걸립니다.**

```js
// 이런 코드는 grep "fa-" 로 잡히지만
el.className = "fas fa-user-pen";

// 이런 코드는 안 잡힌다
el.className = `fas fa-${iconName}`;
```

실제로 이 프로젝트에는 런타임에 `<i>` 태그를 만들어 붙이는 컴포넌트들이 있습니다. 4절에서 *"자주 안 들어가는 페이지"* 에서 깨진 아이콘이 나온 것도, 인벤토리가 정적 마크업 기준이었기 때문일 가능성이 높아요. **grep 인벤토리는 "찾은 것"의 목록이지 "전부"의 목록이 아니었습니다.**

**② 아이콘 로드 방식이 프로젝트 안에서 두 가지입니다.**

3.3의 수정은 **웹폰트 방식**을 전제로 합니다. `font-family: "Font Awesome 7 Free"` + 유니코드 `content`니까요.

그런데 이 프로젝트는 [검색형 select를 만들면서 확인했듯](/blog/검색형-select-복구-searchableselect-회고) FontAwesome을 `all.min.js`로도 로드합니다. **JS가 `<i>`를 `<svg>`로 교체하는 SVG 모드**예요. 그 글에서 겪은 유령 노드 버그가 바로 이 교체 때문이었고요.

한 프로젝트에서 **웹폰트 CSS와 SVG 교체가 같이 돌고 있다**는 뜻입니다. 이번 업그레이드에서는 이 부분을 정리하지 않고 각각 고쳤어요. 두 방식은 깨지는 양상이 달라서(웹폰트는 코드포인트 재배치, SVG는 DOM 교체 타이밍) **다음 메이저 때 점검할 항목이 두 배가 됩니다.** 하나로 통일하는 게 이 업그레이드에 딸려 나왔어야 할 결론이었습니다.

**③ "코드포인트 검증 필요"라고 적어두고 방법을 안 적었습니다.**

```css
content: "\f054";  /* 그래도 코드포인트 검증 필요 */
```

주석은 남겼는데 **무엇을 어떻게 검증했는지가 없어요.** 실제로는 브라우저에서 눈으로 확인한 게 전부였습니다. 아이콘 이름 → 코드포인트 매핑은 공식 메타데이터(`icons.json`)에 있으니, 거기서 뽑아 CSS의 값과 대조하는 스크립트를 짰으면 자동화됐을 겁니다.

**④ 버전 문자열이 CSS에 박혀 있습니다.**

`"Font Awesome 7 Free"`를 리터럴로 썼으니 다음 메이저 때 또 전수 치환해야 합니다. CSS 변수로 한 번 빼두면(`--fa-family`) 다음엔 한 줄만 바꾸면 돼요. 이번 업그레이드가 **딱 그걸 배운 자리인데** 그대로 리터럴을 다시 박았습니다.

**⑤ 자동 캡쳐 도구를 안 붙였습니다.**

이 업그레이드 나흘 뒤에 [시각 회귀용 자동 캡쳐 스크립트](/blog/페이지-자동-캡쳐-스크립트-만들기)를 만들었어요. 아이콘 깨짐이야말로 그 도구가 가장 잘 잡는 종류인데, 순서가 반대였습니다. *"자주 안 들어가는 페이지에서 늦게 발견됐다"* 는 4절의 경험이 그 도구를 만든 동기 중 하나였고요.

---

## 6. 정리

체감으로는 메이저 업그레이드치고 비교적 무사히 끝났습니다. 정리해두면:

- **인벤토리부터** — 어디서 뭘 쓰는지 모르고 시작하면 회귀 점검을 할 기준이 없습니다.
- **CSS의 유니코드 직접 참조가 가장 위험**. 가능하면 마크업으로 옮기기.
- **deprecated alias는 다음 메이저 때 사라진다고 가정**하고 잘 알려진 이름으로 미리 옮겨두기.
- 회귀 점검은 "자주 안 들어가는 페이지"가 가장 늦게 발견됩니다. 의식적으로 끝까지 훑기.

다음 메이저(8.x?)가 나올 즈음에는 이번 글이 단서가 되어 더 빠르게 끝낼 수 있기를 기대합니다.
